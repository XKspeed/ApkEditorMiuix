# ApkEditor·Miuix 开发文档

> 版本：v0.1（固定版本号，不再改动）· 真实引擎已接入（ARSCLib + smali/baksmali + apksig）· 技术栈：Kotlin 2.4 + Jetpack Compose + Miuix 0.9.3
> 最低系统：Android 15（API 35） · 目标系统：Android 17（API 37）

---

## 一、项目概述

仿 MT 管理器的 APK 反编译编辑工具，**只保留 APK 编辑能力，无文件管理器**。
当前为 **UI 预览版**：界面完整可交互，数据层为演示数据（Mock），用于先验收 UI 与交互。
UI 采用 **Miuix**（compose-miuix-ui，小米 HyperOS 设计风格组件库）。

### 界面结构（v0.2.0 起：底部三栏导航）
| 底部 Tab | 页面 | 说明 |
| --- | --- | --- |
| 主页 | 选择 APK → 信息页 → DEX/ARSC/XML 编辑 | 原全部功能入口 |
| 保存的 APK | 打包产物列表（分享/删除） | 持久化存储（SharedPreferences） |
| 设置 | 主题切换（跟随系统/浅色/深色）+ 关于 | 主题即时生效 |

### 功能入口（当前版本）
| 入口 | 说明 | 状态 |
| --- | --- | --- |
| DEX / Smali 编辑 | dex 列表 → smali 文件树 → 代码编辑器（查找/替换/跳行/保存） | UI 完成，逻辑 Mock |
| ARSC 资源编辑 | 资源类型 → 资源条目 → 弹窗编辑值 / 重命名 | UI 完成，逻辑 Mock |
| XML 文件编辑 | XML 文件列表 → 文本编辑器 | UI 完成，逻辑 Mock |
| 打包并签名 | SAF 选择输出位置 → 模拟打包，产物记入"保存的 APK" | UI 完成，逻辑 Mock |

## 四、架构设计

### 4.1 分层

```
┌─────────────────────────────┐
│ UI 层（com.apkeditor.miuix.ui）│  Compose + Miuix 组件
├─────────────────────────────┤
│ 数据层接口（ApkDataService） │  UI 只依赖接口，不依赖实现
├─────────────────────────────┤
│ Mock 实现 / 未来真实实现     │  可替换
└─────────────────────────────┘
```

关键点：**UI 与数据解耦**。所有页面通过 `ApkDataService` 接口取数，
当前注入 `MockApkDataService`；后续接入真实引擎时，实现 `RealApkDataService`
（内部用 ARSCLib + smali/baksmali + apksig），**UI 代码零改动**。

### 4.2 导航（v0.2.0：底部三栏 + 主页子栈）

`App.kt` 顶层是**底部三栏导航**（miuix `NavigationBar` + `NavigationBarItem`）：

```kotlin
// 底部三 tab（常驻，切 tab 保留各 tab 状态）
var tab by remember { mutableIntStateOf(0) }  // 0 主页 / 1 保存的APK / 2 设置
Scaffold(
    contentWindowInsets = WindowInsets(0, 0, 0, 0),
    bottomBar = {
        NavigationBar {
            BottomTab.entries.forEachIndexed { index, item ->
                NavigationBarItem(
                    selected = tab == index,
                    onClick = { tab = index },
                    icon = MiuixIcons.Home / Download / Settings,
                    label = "主页 / 保存的APK / 设置",
                )
            }
        }
    },
) { innerPadding -> Box(Modifier.padding(innerPadding)) { when(tab) { ... } } }
```

**主页 tab 内**再用 `mutableStateListOf<Screen>` 维护子页面返回栈：

```kotlin
sealed interface Screen {
    data object Home : Screen
    data class ApkInfo(val uri: String) : Screen
    data class DexList : Screen
    data class SmaliTree(val dexName: String) : Screen
    data class SmaliEdit(val dexName: String, val filePath: String) : Screen
    data object ArscTypes : Screen
    data class ArscEntries(val type: String) : Screen
    data object XmlFiles : Screen
    data class XmlEdit(val path: String) : Screen
}
```

- 前进：`stack.add(screen)`；返回：`stack.removeLast()`
- 系统返回键：`BackHandler { when { tab != 0 -> tab = 0; stack.size > 1 -> goBack() } }`
- 不依赖 Navigation 库，减少依赖与学习成本

⚠️ insets 约定：**外层** Scaffold 与**所有内层页面** Scaffold 均设
`contentWindowInsets = WindowInsets(0, 0, 0, 0)`，系统栏 inset 统一由各
`TopAppBar` 的 `defaultWindowInsetsPadding` 处理，避免状态栏/导航栏双重 padding。

### 4.3 主题与深色模式（v0.2.0：设置页可切换）

主题模式状态提升为全局单例 `ThemeState`（参考 miuix 官方示例 `ui/Theme.kt`）：

```kotlin
// ThemeState.kt —— 设置页直接改，MainActivity 据此重建 controller
object ThemeState {
    var mode by mutableIntStateOf(0)  // 0=跟随系统 1=浅色 2=深色
}
```

```kotlin
// MainActivity.kt
enableEdgeToEdge()  // Android 15 强制 edge-to-edge，系统栏自动适配
val controller = remember(ThemeState.mode) {
    when (ThemeState.mode) {
        ThemeState.MODE_LIGHT -> ThemeController(ColorSchemeMode.Light)
        ThemeState.MODE_DARK  -> ThemeController(ColorSchemeMode.Dark)
        else                  -> ThemeController(ColorSchemeMode.System)
    }
}
MiuixTheme(controller = controller) { App() }
```

设置页切换（miuix-preference 的 `OverlayDropdownPreference`，与官方示例 SettingsPage 一致）：

```kotlin
OverlayDropdownPreference(
    title = "主题",
    items = listOf("跟随系统", "浅色", "深色"),
    selectedIndex = ThemeState.mode,
    onSelectedIndexChange = { ThemeState.mode = it },
)
```

⚠️ **必须使用带 controller 的 MiuixTheme 重载**。
`MiuixTheme {}`（无参）固定使用默认亮色配色，不跟随系统——这是 v0.1 深色模式失效的根因。
全项目颜色一律通过 `MiuixTheme.colorScheme.xxx` 取用，禁止硬编码颜色。

### 4.5 数据服务接口（ApkDataService.kt）

接口新增 `listApkContents(): Result<List<ApkEntry>>`——用 java.util.zip 直接解压 APK 列全部条目（path+size），用于 APK 内容页的快速文件树预览（不解析）。

```kotlin
interface ApkDataService {

    suspend fun listDexFiles(): Result<List<DexEntry>>

    suspend fun listResourceTypes(): Result<List<ResourceTypeInfo>>
    suspend fun listResources(type: String): Result<List<ResourceEntryInfo>>

    suspend fun renameResource(id: Int, newName: String): Result<Unit>
    suspend fun listXmlFiles(): Result<List<XmlFileInfo>>
    suspend fun readXmlFile(path: String): Result<String>
    suspend fun saveXmlFile(path: String, content: String): Result<Unit>
```

## 五、关键实现说明

### 5.1 通用代码编辑器（TextEditorScreen.kt）

Smali 与 XML 编辑共用，通过 `load` / `save` lambda 注入差异：

| 功能 | 实现 |
| --- | --- |
| 文本编辑 | androidx `TextFieldState` + Miuix `TextField(state=...)` |
| 文本写入 | `state.edit { replace(0, length, newText) }`（receiver lambda，注意不能用 `it`） |
| 光标定位 | `state.edit { selection = TextRange(start, end) }` |
| 脏标记 | `snapshotFlow { state.text.toString() }.collect { dirty = true }` |
| 查找/替换 | 字符串 indexOf / replace + 选中高亮 |
| 跳转行 | 按 `\n` 累计 offset → 设置 selection |

⚠️ androidx 新版文本 API 要点：
- `TextFieldState.text` 是只读 `CharSequence`
- 修改必须通过 `edit {}` 块，块内 receiver 是 `TextFieldBuffer`（用 `this`/隐式 receiver，不能用 `it`）

### 5.2 Miuix 组件使用要点（0.9.3）

| 组件 | 包 | 备注 |
| --- | --- | --- |
| `TopAppBar` | `top.yukonga.miuix.kmp.basic` | 0.9.3 在 basic 包（老文档的 topBar 包已不存在） |
| `Scaffold` | 同上 | 弹窗宿主，`content: (PaddingValues) -> Unit`；本项目全部设 `contentWindowInsets = WindowInsets(0,0,0,0)` |
| `Button / Text / Card / Surface` | 同上 | 均为 Miuix 版本 |
| `HorizontalDivider` | 同上 | **0.9.3 没有 `Divider`，只有 `HorizontalDivider`/`VerticalDivider`** |
| `TextField(state: TextFieldState)` | 同上 | 用 androidx TextFieldState |
| `NavigationBar` | 同上 | 底部导航栏，`content: RowScope.() -> Unit` |
| `NavigationBarItem` | 同上 | 参数：`selected / onClick / icon: ImageVector / label: String`（**参数名是 label 不是 title**） |
| `MiuixIcons.Home / Download / Settings` | `top.yukonga.miuix.kmp.icon` + `...icon.extended` 扩展属性 | 0.9.3 需单独依赖 `miuix-icons-android` |
| `OverlayDropdownPreference` | `...kmp.preference` | 下拉选择项，`title / items / selectedIndex / onSelectedIndexChange`；**双层 Scaffold 时必须 `renderInRootScaffold = false`（否则展开闪退，见 §8 坑 17）** |
| `WindowDropdownPreference` | 同上 | 独立 window 弹窗版下拉（备选，绕开 overlay） |
| `RadioButtonPreference` | 同上 | 单选行（无弹窗），`title / selected / onClick` |
| `SwitchPreference` | 同上 | 开关项，`title / checked / onCheckedChange` |
| `MiuixTheme / ThemeController / ColorSchemeMode` | `...kmp.theme` | 必须用 controller 重载跟随系统 |

### 5.3 弹窗（components/Common.kt）

自实现 `MiuixDialog`（scrim + Surface 圆角卡片），避免依赖不确定的 OverlayDialog API。
`androidx.compose.ui.window.Dialog` 会继承调用点的 CompositionLocal，因此弹窗内颜色随主题正常。

### 5.4 保存的 APK（SavedApkStore.kt）

打包成功时把输出（SAF Uri + 文件名 + 大小 + 时间）写入 SharedPreferences，
「保存的 APK」页读取展示，支持**分享**（`ACTION_SEND` + `FLAG_GRANT_READ_URI_PERMISSION`）与**删除**。
真实引擎接入后 `RealApkDataService.buildAndSign` 同样调用 `SavedApkStore.add`，UI 零改动。

## 六、后续接入真实引擎（路线图）

### 6.1 依赖已就绪

`app/build.gradle.kts` 已预留：
- `com.github.REAndroid:ARSCLib:V1.4.0`（jitpack）
- `org.smali:baksmali:2.5.2` / `org.smali:smali:2.5.2`
- `com.android.tools.build:apksig:8.13.x`（google maven，签名）

### 6.2 计划实现（RealApkDataService）

| 功能 | 方案 | 关键 API |
| --- | --- | --- |
| 打开 APK | ARSCLib `ApkModule.loadApkFile(File)` | 复制 SAF Uri → 缓存目录 |
| APK 信息 | `apkModule.getAndroidManifestBlock()` | getPackageName / getVersionName / getUsesPermissions |
| XML 解码 | `apkModule.decodeXMLFile(path)` → XMLDocument | `XMLFactory.newSerializer(Writer)` 输出文本 |
| XML 编码 | `XMLEncodeSource(packageBlock, XMLFileParserSource(path, file))` | `apkModule.add(source)` 替换 |
| DEX 反汇编 | baksmali | `Baksmali.disassembleDexFile(dexFile, dir, api, options)` |
| DEX 汇编 | smali | `Smali.assemble(options, smaliDir)` |
| 资源编辑 | ARSCLib | `TableBlock.getResources()` → `ResourceEntry` → `Entry.setValueAsString()` |
| 打包 | `apkModule.writeApk(File)` | 替换 dex / xml 后写回 |
| 签名 | apksig | v1 + v2，自动生成调试密钥 |

### 6.3 注意事项

- 只能处理**未加固** APK
- 全部工作在 App 私有缓存目录，无需 Root
- smali 汇编是整 dex 级（baksmali 全量 → 改 → smali 全量汇编）
- ARSC 编辑走二进制资源表直改，规避 aapt2 在 Android 端的兼容问题

## 八、已知限制

1. 当前为 UI 预览版，**数据为演示数据**，不具备真实反编译能力
2. Miuix 库处于实验阶段，升级版本可能破坏编译
3. 编辑器暂不做语法高亮（后续可扩展）
4. 仅支持未加固 APK（后续版本）
5. 主题选择暂未持久化（重启后回到跟随系统，后续可接入 DataStore）
